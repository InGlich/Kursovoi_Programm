# Формирование и анализ архива событий инфраструктуры

**Вариант 27 — Брокер сообщений**  
**Уровень сложности — 2 (средний)**  
**Язык реализации — C**

## Описание проекта

Брокер сообщений передаёт данные между сервисами. Для наблюдения за его работой используются сведения о количестве сообщений и задержке на каждом узле.

Программа читает текстовые события из стандартного ввода, разбирает их в структуры `Event` и накапливает в оперативном буфере. При архивации программа удаляет дубликаты, выполняет поиск по количеству сообщений, сортирует записи по задержке и сохраняет результат в `archive.txt`.

## Индивидуальное задание

1. Читать события брокера сообщений в формате `час:минута node messages lag`. Хранить каждое событие в структуре `Event` из пяти полей.
2. Архивировать накопленный буфер, когда по временным меткам прошло не менее 60 минут.
3. Удалять дубликаты. Две записи считаются дубликатами, если совпадают идентификатор узла и количество сообщений, а разница во времени составляет не более 10 минут.
4. Находить все записи, в которых количество сообщений строго выше заданного порога. В программе установлен порог `100`.
5. Сортировать записи по задержке в порядке убывания.
6. Записывать обработанные события в файл и выводить количество принятых событий, удалённых дубликатов и записей в архиве.

## Формат входных данных

Одна строка содержит одно событие.

```text
10:15 2 120 15
```

| Поле `Event` | Назначение | Значение в примере |
| --- | --- | --- |
| `h` | Час события, от 0 до 23 | `10` |
| `m` | Минута события, от 0 до 59 | `15` |
| `node` | Идентификатор узла брокера | `2` |
| `messages` | Количество сообщений | `120` |
| `lag` | Задержка | `15` |

## Порядок обработки

Программа хранит до 1000 записей в массиве `Event`. Перед добавлением очередной записи она сравнивает её время со временем первого события в буфере. Если прошло 60 минут или больше, накопленный буфер архивируется, а очередная запись начинает новый период. При вычислении интервала учитывается переход через полночь.

В пределах каждого периода программа последовательно сравнивает записи с уже сохранёнными уникальными событиями. Если найден дубликат, сохраняется более ранняя по порядку ввода запись. Для определения дубликата учитываются `node`, `messages` и разница во времени. Значение `lag` используется при сортировке.

При срабатывании регламента программа ищет среди уникальных событий все записи с `messages > 100` и выводит их количество. Затем она сортирует весь обработанный буфер по убыванию `lag` и дописывает его в `archive.txt`. Сортировка выполняется отдельно для каждого периода.

При вводе `q` или достижении конца входного потока программа удаляет дубликаты из остатка буфера, сортирует его и дописывает в архив. Поиск по порогу в этой ветке программы пропускается.

## Основные функции

| Функция | Что принимает | Что возвращает | Что делает |
| --- | --- | --- | --- |
| `parse_event(const char *line, Event *event)` | Строку `line` и указатель на структуру `event` | `1` при успешном разборе, `0`, если не удалось прочитать пять полей или время выходит за допустимые границы | Извлекает пять целых чисел через `sscanf`, заполняет поля `Event` и проверяет часы и минуты. |
| `time_to_minutes(int h, int m)` | Час `h` и минуту `m` | Число минут от начала суток | Вычисляет `h * 60 + m`. |
| `get_time_diff(int h1, int m1, int h2, int m2)` | Время двух событий | Кратчайший интервал между ними в минутах | Переводит обе отметки в минуты. Если абсолютная разница больше 720 минут, вычитает её из 1440. |
| `should_archive(Event first, Event current)` | Первое событие буфера и очередное событие | `1`, если прошло не менее 60 минут, иначе `0` | Вычитает время первого события из времени очередного. При отрицательной разнице прибавляет 1440 минут. |
| `is_duplicate(Event e1, Event e2)` | Две записи | `1`, если записи являются дубликатами, иначе `0` | Сравнивает `node` и `messages`, затем проверяет, укладывается ли разница во времени в 10 минут включительно. |
| `filter_duplicates(Event *buffer, int count, int *discarded)` | Буфер, число записей и указатель на счётчик дубликатов | Число записей после фильтрации | Собирает уникальные события во временный массив, переносит их в начало `buffer` и записывает число дубликатов в `*discarded`. |
| `search_above_threshold(Event *buffer, int count, int threshold, Event *found)` | Буфер, число записей, порог и массив для результатов | Число найденных событий | Копирует в `found` записи, у которых `messages > threshold`. |
| `compare_lag_desc(const void *a, const void *b)` | Указатели на две записи `Event` | Отрицательное число, если `lag` первой записи больше, положительное, если меньше, или `0` при равенстве | Задаёт для `qsort` порядок убывания задержки. |
| `write_archive(const char *filename, Event *buffer, int count)` | Имя файла, обработанный буфер и число записей | `void` | Открывает файл в режиме дозаписи, записывает события по одному на строку и закрывает файл. При ошибке открытия выводит сообщение. |

Объявления вспомогательных функций расположены до `main`, определения — после. Функция `main` организует ввод, обработку периодов и вывод итоговой статистики.

## Сборка и запуск

Выполните команды из каталога с `main.c`. Для сборки нужен компилятор C с поддержкой стандарта C11.

```bash
cc -std=c11 -Wall -Wextra -Wpedantic main.c -o broker
./broker
```

Вводите по одному событию на строку. Для завершения введите `q`. Файл `archive.txt` создаётся в рабочем каталоге при первой записи. Для воспроизведения примера начните с пустого архива, поскольку программа дописывает новые строки в конец файла.

## Демонстрация работы

### Входные сообщения

```text
10:00 1 50 5
10:05 1 50 8
10:15 2 120 15
10:40 1 200 10
11:01 3 300 25
q
```

### Буфер перед первой архивацией

Между `10:00` и `11:01` проходит 61 минута. Событие `11:01` запускает обработку этих четырёх записей и открывает следующий период.

| Индекс | `h` | `m` | `node` | `messages` | `lag` |
| --- | --- | --- | --- | --- | --- |
| `buffer[0]` | 10 | 00 | 1 | 50 | 5 |
| `buffer[1]` | 10 | 05 | 1 | 50 | 8 |
| `buffer[2]` | 10 | 15 | 2 | 120 | 15 |
| `buffer[3]` | 10 | 40 | 1 | 200 | 10 |

### Дубликаты и результат обработки

- Запись `10:05 1 50 8` удаляется как дубликат записи `10:00 1 50 5`. У обеих записей `node = 1`, `messages = 50`, а разница во времени составляет 5 минут.
- После фильтрации остаются три записи. Условию `messages > 100` соответствуют события `10:15` и `10:40`.
- После сортировки первый период записывается в порядке `10:15` (`lag = 15`), `10:40` (`lag = 10`), `10:00` (`lag = 5`).
- После ввода `q` программа дописывает единственную запись второго периода — `11:01 3 300 25`.

### Содержимое `archive.txt`

```text
10:15 2 120 15
10:40 1 200 10
10:00 1 50 5
11:01 3 300 25
```

### Итоги запуска

| Период | Записей до фильтрации | Удалено дубликатов | Записано в архив |
| --- | --- | --- | --- |
| Первый | 4 | 1 | 3 |
| Второй | 1 | 0 | 1 |
| Всего | 5 | 1 | 4 |

## Заключение

Программа формирует архив событий брокера из текстового потока. Контрольный пример показывает срабатывание 60-минутного регламента, удаление дубликата, поиск по количеству сообщений, сортировку по задержке и запись остатка буфера при завершении.
